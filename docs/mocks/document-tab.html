Patton Document Tab

Open what Claude hands you, Word files, PDFs and Claude's own pages, in a Patton tab beside your session, without hunting in Downloads or switching to Word.

Four ways to do it, from what researching the options and testing on this Mac turned up. The first two work today at low risk. The last two are about Claude's pages, and one of them needs a short test first.

StepTime
Build2 min
  • A click on a Word file (in the session bar, a bookmark, or the terminal) opens it in a new Patton tab as a page-width view, like a clean web page. Page breaks appear only where the file has them, and 383 of your last 503 Word files have none, so most read as one long sheet. PDFs open in the PDF viewer built into Patton.
  • Buttons: Open in Word, Show in Finder, Copy (formatting kept), Find, Zoom. It reloads when Claude rewrites the file.
  • Headings, tables and images come through. Comments and tracked changes show too, though the library calls those experimental.
  • Fields aren't recalculated: a table of contents shows the text Word last saved in it, and page numbers are dropped.
  • One small library (docx-preview, Apache-2.0, with its zip reader; no install scripts; 0 audit issues today), shown in a locked-down frame so nothing in a document can run.

B · Print view, a button on A

A "Print view" button lays the Word file out as printed pages through LibreOffice, which is already on this Mac: close to Word's pages, not identical. Comments go in the margin with their author, and tracked changes are marked with a change bar. About 1–2 seconds for a one-page file, longer for long ones. Text copied from it likely loses headings and bold, so A stays the default view.

  • The real page, exactly as in Chrome: comments and live data included.
  • You sign in to claude.ai once, inside Patton. Google's sign-in can refuse apps that embed a browser, so it would be by email link.

Today, what Claude has running in the background is hidden at the bottom of its screen…
  • Claude's page tool only takes a file from this Mac, so every page it publishes starts as one: in the last four days, 11 pages (38 publishes, counting updates), each with its file still here. Patton shows that file at once, and again whenever Claude rewrites it.
  • No sign-in. Pages from the last four days loaded only Google Fonts; a page that pulls a library from the web would load it too unless Patton blocks it.
  • It isn't the live page: no comments, and nothing made on another computer. "Open live in Chrome" covers that.

Recommendation

  • Build A with B's button, and send the session bar's and bookmarks' Word, PDF and page links there.
  • For Claude's pages, D now. C only if a one-hour sign-in test passes, since it would hold your claude.ai login inside Patton.
  • Ruled out:
    • Quick Look: a floating panel, not a tab, and it drops comments and deletions.
    • mammoth, another Word library: it silently drops deleted text.
    • Google Docs, which stay in Chrome for the same sign-in reason as C.
