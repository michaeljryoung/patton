How it behaves

  • Live login first, in bold with a "live" tag. The others keep their last reading. A login you aren't using doesn't move, so its number stays true until its reset.
  • After a reset, a login that hasn't been live since shows 0% and "reset Sat 08:00", because its week started over.
  • Colour only for meaning, as everywhere in Patton: ink bars, amber from 80%, red at 100%.
  • 5-hour line only for a login whose plan reports one. Your live login reports a weekly limit only right now.
  • With the sidebar hidden, the narrow strip down the left would show the three bars stacked, with the figures in a tooltip.

What a token count can mean

Anthropic reports each limit as a percent and a reset time. It doesn't give a token count, so any count has to come from Claude Code's own records of each request. Patton would add up the tokens each login spent since its week began, using the record of which login was live when.

Almost all tokens are Claude re-reading the conversation from its cache. Those cost a twentieth of fresh ones. Counted raw, they swamp everything else, and 1% of a week stops being a steady number. Weighted by price counts each token at its share of the cost. That figure tracks the limit, so it compares logins whose plans differ.
