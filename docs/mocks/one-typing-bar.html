How A finds Claude's bar

  • Claude Code v2.1.321, the version on this Mac, has nothing that hides its bar. I checked the program itself: its settings, its environment switches and the eight terminal features it asks a terminal about.
  • Every time it redraws, Claude Code parks the terminal's cursor on its own ❯ line, between a ─ rule above and one below. I replayed a real Claude Code session through the same terminal engine Patton uses: the cursor rested on the bar at start-up, and after 22 of 26 bursts of output during a turn. The other 4 bursts ended halfway through a redraw, and the cursor was back on the bar after the next one. So Patton reads the bar's position only once the screen has settled.
  • If a later Claude Code draws its bar differently, Patton won't see that pattern and puts the box back under the terminal, as it is today. It never covers rows it hasn't recognised.
  • When you hand the keyboard to Claude's own bar (Esc with a draft), the box moves off it so you can see what you type there. With the box switched off in Settings, everything is as before v1.31, the Okay? row included.
