# Claude state, file links and the startup command

Read before touching Claude Code state detection (OSC 7501, the Stop hook, title glyphs), OSC 133 prompt handling, file-link opening, or anything that depends on the startup command. Moved word for word from CLAUDE.md's Gotchas (S46 slimming, 2026-11-08). From the S66 slimming it also holds the compose box's reading of Claude's bar, the Stop hook's sequence limit, and which pane state means work is running.

- **Answering Claude Code's `OSC 7501;?` probe makes Claude drop its ◐/✳ title glyph** (S43). From v1.14 Patton answers it (setting `programStatus`, default on), so a pane's Claude state comes from 7501 reports (`services/program-status.ts`, `Pane.claudeState`) and the title glyph + Stop-hook verdict are only the fallback for panes that never report. One exception (S46): 7501 can report a turn done with no child tasks while Claude Code's own task list, which the hook reads, still has some (seen with agents waiting on their own shells; why 7501 drops them is unconfirmed), so a turn's hook verdict with tasks or crons > 0 still turns 7501's plain "done" into the ring (`services/turn-end.ts`; before that, 9 of 60 greens fired while background work ran). A second (S61): Claude Code 2.1.321 keeps the root `working` after a turn ends while a subagent it launched runs, and sends no `done` until the subagent's notification starts the next turn; so a Stop verdict over a working root with working children shows the ring at once (`[DOT] Turn ended over a working root`, source `hook-root-working`), left on any change of the root or of the working children, on his own send, or when main's transcript feed (`turn-activity`) shows another Stop hook blocked that stop or Claude wrote again; a fast blocker's line can reach the pane ~120 ms before the verdict, so a block seen up to 2 s before it (and after the previous Stop) means no ring at all (`blocked: true` on the log line). A send that may run locally (a `/` or `!` line, such as `/usage`) leaves the ring to the feed's next assistant line (`[DOT] Ring kept: a local command`). Only a pane whose feed main has attached shows this ring (`feed` on the log line); without it, or once main detaches (`[DOT] Turn-end ring dropped: no feed`), the pane waits for 7501 as before (main.log 10–22 Nov: 2,752 such Stops, 48 followed by a `done`; transcripts 16–22 Nov: 45 of 3,424 Stops blocked, 16 with a background subagent running). If dots misbehave, Settings → "Use Claude Code's own status reports" off restores the v1.13 path for Claude sessions started after the change; `grep '\[7501\]' main.log` shows probe answers and states. Only reports with `app=claude-code` count as Claude.
- **A file link may only open what can't run** (S43). `src/main/link-open-policy.ts` decides open / editor / reveal for every file link (bare text, markdown, OSC 8): realpath first, then only regular, non-executable view types open in their default app (HTML/SVG/PDF go to Chrome/Acrobat here, where page script can run); `.docx`/`.xlsx`/`.pptx` open in Office (S60), the macro-enabled `.docm`/`.xlsm`/`.pptm` and their templates are revealed; code goes to the editor; apps, scripts, installers, `.webloc` and unknown types are revealed in Finder. `scripts/check-link-open-policy.mjs` drives the real handler with recorders; never test by opening fixtures.
- **Michael's startup command is `cc`, a project picker, not `claude`** (S42). It always asks which project, so a bookmark tab that just typed it landed in the picker. A tab opened from a project bookmark now gets `PATTON_PROJECT_DIR` (first pane only; main exports the validated cwd, the renderer sends only `projectDir: true`), and `cc` in `~/Projects/claude-launcher/launcher.sh` uses it once to launch that project directly. Never assume what the startup command does.
- **OSC 133 `'prompt'` is not "awaiting input".** Fires on every prompt redraw — shell startup, session restore, SIGWINCH, `clear`, async-prompt refreshes (Starship, Powerlevel10k). Use `pane.ts fireCommandDone()` for the meaningful-transition signal.

## Gotchas moved from CLAUDE.md (S66 slimming, 2026-11-25)

- **The dot's activity word (`Pane.currentActivity`) is ranked for alerting, not for "is work running"** (S62). An error root outranks working children, and the hook's verdict drops when children drain, so Pause all reads `pauseInput().running`; don't reuse the activity word for a decision about running work.
- **The box finds Claude Code's bar on screen, so a Claude Code redesign of that bar quietly puts the box back under the terminal** (S58). `services/claude-bar.ts` needs the cursor's row to start with `❯` between two all-`─` rows; Claude's hint text is dim, his typed text is not. When the box stops covering the bar, `grep '\[COMPOSE\] bar not found' main.log` gives why (no-glyph, no-rule-above, no-rule-below); then re-record `scripts/fixtures/claude-bar-screens.json` from the new Claude Code (a pty capture with `--settings '{"disableAllHooks":true}'`; run from inside a Claude session, its transcripts stay off).
- **A hook's `terminalSequence` over 4096 bytes is dropped whole by Claude Code** (S60, read in 2.1.321). The Stop hook keeps its sequence under 3,500 by cutting its lists, never the sequence; a renderer that reads a list must treat a short one (fewer items than `tasks`) as cut.
- **Claude Code keeps its 7501 root `working` after a turn ends while a subagent it launched still runs** (S61, 2.1.321). No `done` comes until the subagent's `<task-notification>` starts the next turn, so a pane that waited for `done` showed nothing for the whole run (House tab, 22 Nov). A Stop verdict over a working root with working children is the turn end (`turnEndedOverWork` in `services/turn-end.ts`); his send, or the transcript feed's `turn-activity` (a Stop another hook blocked, a new assistant line), is the next turn's only sign, since the root already reads working. So the ring shows only on a pane whose feed main has attached; a blocked Stop's line can arrive before the verdict, and a `/` or `!` line he sends may start no turn. Background shells still get their `done`. An Esc that stops a turn sent over it changes nothing in 7501 either (the root stays `working`): D18's restore reads Claude's bar instead (`planHoldsSent`).
