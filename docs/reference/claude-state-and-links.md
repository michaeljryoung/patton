# Claude state, file links and the startup command

Read before touching Claude Code state detection (OSC 7501, the Stop hook, title glyphs), OSC 133 prompt handling, file-link opening, or anything that depends on the startup command. Moved word for word from CLAUDE.md's Gotchas (S46 slimming, 2026-11-08).

- **Answering Claude Code's `OSC 7501;?` probe makes Claude drop its ◐/✳ title glyph** (S43). From v1.14 Patton answers it (setting `programStatus`, default on), so a pane's Claude state comes from 7501 reports (`services/program-status.ts`, `Pane.claudeState`) and the title glyph + Stop-hook verdict are only the fallback for panes that never report. One exception (S46): 7501 can report a turn done with no child tasks while Claude Code's own task list, which the hook reads, still has some (seen with agents waiting on their own shells; why 7501 drops them is unconfirmed), so a turn's hook verdict with tasks or crons > 0 still turns 7501's plain "done" into the ring (`services/turn-end.ts`; before that, 9 of 60 greens fired while background work ran). If dots misbehave, Settings → "Use Claude Code's own status reports" off restores the v1.13 path for Claude sessions started after the change; `grep '\[7501\]' main.log` shows probe answers and states. Only reports with `app=claude-code` count as Claude.
- **A file link may only open what can't run** (S43). `src/main/link-open-policy.ts` decides open / editor / reveal for every file link (bare text, markdown, OSC 8): realpath first, then only regular, non-executable view types open in their default app (HTML/SVG/PDF go to Chrome/Acrobat here, where page script can run); code goes to the editor; apps, scripts, installers, `.webloc` and unknown types are revealed in Finder. `scripts/check-link-open-policy.mjs` drives the real handler with recorders; never test by opening fixtures.
- **Michael's startup command is `cc`, a project picker, not `claude`** (S42). It always asks which project, so a bookmark tab that just typed it landed in the picker. A tab opened from a project bookmark now gets `PATTON_PROJECT_DIR` (first pane only; main exports the validated cwd, the renderer sends only `projectDir: true`), and `cc` in `~/Projects/claude-launcher/launcher.sh` uses it once to launch that project directly. Never assume what the startup command does.
- **OSC 133 `'prompt'` is not "awaiting input".** Fires on every prompt redraw — shell startup, session restore, SIGWINCH, `clear`, async-prompt refreshes (Starship, Powerlevel10k). Use `pane.ts fireCommandDone()` for the meaningful-transition signal.
