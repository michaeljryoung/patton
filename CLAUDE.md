# Patton

Always-passthrough terminal with a floating compose panel for drafting multi-line input.

## Tech Stack
- **Electron** (v40) with Vite + TypeScript via Electron Forge
- **xterm.js** v6 (`@xterm/xterm`) — terminal rendering (WebGL addon)
- **node-pty** — PTY spawning in main process
- **electron-store** — persistent settings + history

## Architecture

```
src/
├── main/           # Electron main process (PTY, IPC, menus, settings store)
├── preload/        # contextBridge API (type-safe IPC bridge)
├── renderer/       # UI components, services, styles
│   ├── components/ # Tab, Terminal, Compose Panel, Settings, Command Palette, etc.
│   ├── services/   # Tab manager, history, keybindings
│   └── styles/     # CSS with design tokens + auto dark/light mode
├── shared/         # IPC channel constants + shared TypeScript types
└── resources/      # Shell integration scripts (zsh, bash)
```

## Commands
- `npm start` — dev mode with hot reload
- `npm run package` — build distributable
- `npm run make` — create DMG installer
- `npm run lint` — ESLint
- `npm run release [-- patch|minor|major]` — manual release (CI handles this automatically)

## Verifiers

```bash
npm run lint && npm run package
```

## Key Conventions
- All colors use CSS variables (`:root` + `@media prefers-color-scheme`)
- All interactive elements have ARIA attributes
- Resize observers are debounced (100ms)
- PTY data is write-coalesced (4ms buffer)
- electron-store needs CJS/ESM interop: `(mod.default || mod)`
- Entry files must match package.json `main` field naming (main.ts → main.js, preload.ts → preload.js)

## Mission Synthesis
Patton is a macOS Electron terminal (xterm.js, node-pty) built to close the gaps Claude Code exposes in stock terminals: colour queries, contrast, attention signals, and finding your way across many parallel sessions. It ships as a DMG plus a Homebrew cask, CI-versioned on push to main (patch ≤500 lines, else minor; a head commit carrying `[no-release]` skips the whole push), released at **v1.13.2** on Electron 44. S40–S41 made the green dot mean "needs you" (a Claude Code Stop hook's verdict, sent as OSC 777, parks a tab with a hollow ring while the session waits only on its own background work) and added `wake` → yellow, image paste, a bookmarks sidebar with drag-to-reorder and a hide strip, the Trial Stack look and compose-first mode behind a toggle. S42 turned field use into three fixes, released in v1.13.1 (S43): the multi-line paste dialog, which dictation tripped on every message, is a setting off by default; hook verdicts live 40 s, because Claude Code shows ✳ only after every Stop hook and source-critic stretches that to 31 s; and a bookmark for a closed project exports `PATTON_PROJECT_DIR`, which Michael's `cc` reads once to open that project instead of its picker. S43 shipped v1.13.1 and, from a two-agent review after the restyle, v1.13.2's twelve fixes (the worst: autosave saved no folder for panes past the tenth, so they reopened in `~`). The next arc is the live checks, the review's proposals (jump to the waiting session, worktree-aware names, Claude Code's OSC 7501 status), then Forge 8. Builds never land in /Applications mid-session (worktrees, `PATTON_NO_INSTALL=1`, `git merge --ff-only`); Node 26 makes Forge exit 0 without packaging, so proof is the asar's mtime; npm 12 skips unapproved install scripts; a red cask step means the tap's deploy key. DOM is the default renderer and `backgroundThrottling: false` stays load-bearing. Lessons: read the real mechanism, the user's own startup command included, before designing on an assumption; set timeouts from measured data, since each extra second trades one failure for another; exit code 0 is not a build; a fresh reviewer finds what the builder cannot.

## Gotchas
- **Every commit on main reinstalls /Applications/Patton.app, and Michael works inside it** (S41). The post-commit hook runs `scripts/forge-package.sh`, whose postPackage `ditto`s over the running app (survivable, but not wanted mid-session). Do code in a `.worktrees/` worktree (the hook exits there), verify with `PATTON_NO_INSTALL=1 npm run package`, move main with `git merge --ff-only` (no post-commit), and commit on main itself only with `PATTON_NO_INSTALL=1` in the environment (the hook inherits it).
- **Renderer components can be checked headlessly in jsdom** (S41). Bundle the component with `node_modules/.bin/esbuild <entry> --bundle --format=cjs --platform=browser --loader:.css=empty`, set jsdom's window and document as globals with a stub `window.patton`, and dispatch events (drag events: a plain `Event` with `dataTransfer` and `clientY` defined on it). Install jsdom in the scratchpad, not the project. jsdom does no layout, so rect-based logic is only half-tested.
- **`backgroundThrottling: false` is load-bearing, and it makes `document.hidden` useless** (S27; two entries merged S41, originals in the archive). With Chromium's default throttling a backgrounded window's WebGL glyph atlas came back stale (garbled until a resize), so removing the setting brings that back for WebGL users. Side effect: the Page Visibility API always reports visible, so gate "is the user looking?" on `document.hasFocus()`, never `document.hidden` (already so in `app.ts:33`).
- **Michael's startup command is `cc`, a project picker, not `claude`** (S42). It always asks which project, so a bookmark tab that just typed it landed in the picker. A tab opened from a project bookmark now gets `PATTON_PROJECT_DIR` (first pane only; main exports the validated cwd, the renderer sends only `projectDir: true`), and `cc` in `~/Projects/claude-launcher/launcher.sh` uses it once to launch that project directly. Never assume what the startup command does.
- **electron-store fills `defaults` only at the top level** (S42). Patton's settings are one nested object, so a field added later is absent from every saved file: read it as `=== true` (off by default) or `!== false` (on by default), never bare.
- **A new per-pane setting must be applied in `Tab.createPaneInstance`, not only to existing panes** (S40). Until `8af2355`, `Tab.setFont/Scrollback/Theme/Renderer/CopyOnSelect` looped over `_panes`, so a split pane got none of them — on the default DOM renderer a split silently ran WebGL. The review of compose-first found it; keep the values on `Tab` and apply them at pane creation.
- **Under Node 26 `electron-forge package` exits 0 without packaging** (S40). `extract-zip` 2.0.1 opens the first entry of the Electron zip and the event loop drains; Forge prints no error, `out/` stays empty, the postPackage hook never runs, and `/Applications/Patton.app` keeps the previous build (it was the 3 Nov build until 6 Nov). Always build through `scripts/forge-package.sh`; a build is proven only by `ls -l /Applications/Patton.app/Contents/Resources/app.asar` being newer than the commit. The post-commit hook writes its output to `.git/post-commit-build.log`.
- **xterm.js swallows paste events** (S40). Its textarea/`.xterm` paste listener calls `stopPropagation()`, so a bubble-phase `paste` handler on an ancestor never fires for terminal pastes — Patton's sanitise-and-confirm path had been dead since it was written. Use a capture-phase listener and hand text to `terminal.paste()` (keeps bracketed paste), never `pty.write`.
- **A Stop-hook verdict can land while the title still shows ◐** (S40). Claude Code emits each hook's `terminalSequence` as that hook finishes, and Michael's `closing-block-gate.py` can `block` the stop so the turn continues. `pane.ts` therefore stores the verdict and applies it only after ✳ has held 1.5 s; a verdict expires after 40 s (S42: ✳ appears only after every Stop hook ends, and `source-critic.py` makes that 4.5–31 s, so the original 10 s let stops fall through to the title path and go green while background work ran; longer would widen the window where a blocked stop's stale verdict parks a pane that then stops at a question or dialog); a parked pane never fires from the title path. `grep '\[DOT\]' main.log` shows stored/applied (with `afterMs`)/expired.
- **Claude Code's `terminalSequence` allowlist is OSC 0/1/2/9/99/777 + BEL** (S40). Anything else makes the field silently ignored. Patton's channel is `OSC 777;patton;…`; `OSC 777;notify;title;body` counts as attention like OSC 9.
- **npm 12 skips every dependency's install scripts unless `package.json` approves it** (S39). The install still "succeeds", with a warning, and the build fails later (node-pty unbuilt). After adding or bumping a native dependency, run `npm approve-scripts --allow-scripts-pending` and approve with `npm install-scripts approve <pkg> --allow-scripts-pin=false`. CI's npm (11) ignores the field.
- **Claude Code's title glyphs drive the green dot** (S37). - **macOS does NOT hot-swap a replaced `.app` bundle.** After `npm run package` reinstalls to `/Applications/Patton.app`, the running Patton process is still the OLD binary. ⌘Q + relaunch required to pick up new code. If process start < asar mtime, the running build is stale. S26 (2026-04-27 evening) hit this exactly. Second confirmation channel: grep `main.log` for the post-fix log signature.
