# Patton

Always-passthrough terminal with a floating compose panel for drafting multi-line input.

## Tech Stack
- **Electron** (v40) with Vite + TypeScript via Electron Forge
- **xterm.js** v6 (`@xterm/xterm`) — terminal rendering (WebGL addon)
- **node-pty** — PTY spawning in main process
- **electron-store** — persistent settings + history

## Architecture

```
src/
├── main/           # Electron main process (PTY, IPC, menus, settings store)
├── preload/        # contextBridge API (type-safe IPC bridge)
├── renderer/       # UI components, services, styles
│   ├── components/ # Tab, Terminal, Compose Panel, Settings, Command Palette, etc.
│   ├── services/   # Tab manager, history, keybindings
│   └── styles/     # CSS with design tokens + auto dark/light mode
├── shared/         # IPC channel constants + shared TypeScript types
└── resources/      # Shell integration scripts (zsh, bash)
```

## Commands
- `npm start` — dev mode with hot reload
- `npm run package` — build distributable
- `npm run make` — create DMG installer
- `npm run lint` — ESLint
- `npm run release [-- patch|minor|major]` — manual release (CI handles this automatically)

## Verifiers

```bash
npm run lint && npm run package
```

## Key Conventions
- All colors use CSS variables (`:root` + `@media prefers-color-scheme`)
- All interactive elements have ARIA attributes
- Resize observers are debounced (100ms)
- PTY data is write-coalesced (4ms buffer)
- electron-store needs CJS/ESM interop: `(mod.default || mod)`
- Entry files must match package.json `main` field naming (main.ts → main.js, preload.ts → preload.js)

## Mission Synthesis
Patton is a macOS Electron terminal with always-passthrough xterm.js input and a floating compose panel for multi-line drafting, built to close stock-terminal gaps Claude Code exposes (colour-query responses, COLORFGBG, contrast safety net, attention indicators). Feature-complete and distributed at v1.8.0 (DMG + Homebrew tap, self-signed, CI auto-versioned on push to main). Its defining saga — garbled-glyph corruption in xterm's WebGL glyph atlas — closed across S24–S30 with a structural fix: a GPU-free DOM renderer, default since S30, WebGL a one-click opt-in. v1.8.0 (S33) scoped close-confirmation to whole-tab closes (split panes close instantly on ⌘W), added the ⌃⌘N notes scratchpad (persistent encrypted plain-text sidebar — deliberately a docked panel, not a split-tree node), and permanently fixed Homebrew auto-update with a write-scoped SSH deploy key (replaces the expired `HOMEBREW_PAT`; confirms green on the next release). S34 validated the notes panel in real use and exposed the next arc: the Settings Keyboard Shortcuts grid is a hand-maintained HTML block that silently drifted (~8 shortcuts missing, ⌃⌘N included) — the mandated fix, URGENT and first next session, is a single shortcuts registry in shared constants feeding menu, command palette, and a runtime-rendered grid, so future shortcuts appear automatically. Then backlog: OSC 8 hyperlinks, dev-dep CVE pass, double-click-link validation, S20 punch-list. Constraints: self-signed dist, ⌘Q+relaunch after packaging, cosmetic 1.0.0 version string (git tags are source of truth). Guiding lessons: suspect the layer not the dose when a closed bug returns; scope guards to the accident they prevent; hand-maintained duplicates of code-defined facts always drift — generate them.

## Decisions
- **2026-07-07 (S34) — Shortcuts-list fix must be structural, not additive.** ⌃⌘N was missing from Settings' Keyboard Shortcuts because the grid is a hand-maintained HTML block (`settings-panel.ts:138`) — audit found ~8 shortcuts had drifted out, not one. User directive: hand-adding the rows is ruled out as an end-state; required fix is one shortcuts registry (`src/shared/constants.ts`: id + label + Electron accelerator + display keys) read by `menu.ts`, the command palette, and a runtime-rendered Settings grid. Acceptance: a new shortcut appears in Settings with zero `settings-panel.ts` edits. Fix deliberately deferred — user was mid-session in the live app; docs-only commits only (`ace9d1e`, `a8a7209`).
- **2026-07-07 (S33) — Scoped close-confirmation to whole-tab closes; pane closes are instant.** S31 bundled pane-close into the tab-close guard, but the Cancel-defaulted dialog turned the natural ⌘W-then-Enter into a *cancel* → users literally couldn't close a pane. The S31 ask was about accidental *tab* loss; closing one pane of a split is low-stakes (tab + sibling panes survive, scrollback saved for ⌘⇧T). So ⌘W on a multi-pane tab now closes the focused pane with no prompt (iTerm2's idle-split behaviour); whole-tab and ✕/middle-click still confirm. Partially supersedes the S31 "confirm-on-close covers tab+pane" decision.
- **2026-07-07 (S33) — Notes pane is a docked sidebar, not a split-tree node.** `Pane` is deeply terminal-coupled (PTY, compose, session serialization, PTY routing); making the split tree polymorphic to hold a notes leaf would touch the most critical code in the app for marginal benefit. A right-docked panel (sibling of `#content`, toggled by ⌃⌘N, persisted in electron-store) delivers "notes alongside your work" while leaving pane/split/session/PTY untouched — minimal-diff, KISS. Trade-off accepted: one notes surface per window, fixed dock position (not arbitrary split placement) — fine for a scratchpad. Flagged the placement as a judgment call for the user (built while he was on a call).
- **2026-07-07 (S33) — Homebrew auto-update fixed with an SSH deploy key, not a refreshed PAT.** Refreshing `HOMEBREW_PAT` needs the browser (no CLI PAT minting) and would re-expire. A write-scoped deploy key is CLI-mintable, least-privilege (writes ONLY the tap repo vs the PAT's all-repo scope), and never expires. Cost: a workflow edit (HTTPS+PAT clone → SSH clone) — contained to the already-failing cask step, so zero blast radius on the release itself. Validated the key + the exact runner logic (env-var→file→`GIT_SSH_COMMAND`→clone) end-to-end locally before trusting it. Held the workflow push behind `[no-release]` to avoid a spurious release. Supersedes the S30 "fix the tap by hand each release" decision.
- **2026-06-30 (S31) — Recovered the crashed session's work rather than redoing it.** The terminal crash left the confirm-before-close feature uncommitted but intact on disk; transcript forensics (the `last-prompt` record + the final tool calls) + file mtimes reconstructed both the intent and the state. Re-verified (lint clean; the 2 `tsc` errors are pre-existing in *untouched* files — notification-sound typing in `store.ts`/`settings-panel.ts` — not from this work) and committed as-is. Embodies the standing crash-recovery drill: on-disk work survives; only conversation state is at risk, so reconstruct rather than rebuild.
- **2026-06-30 (S31) — Confirm-on-close covers tab + pane, not just app-quit.** S22 only guarded ⌘Q / close-last-window; the *common* accident is ⌘W on a non-last tab. Extended the guard to ✕/middle-click + ⌘W via a reusable `ConfirmDialog`, but deliberately SKIP the last-tab case (it falls through to the app-quit guard → no double prompt) and never prompt on automatic PTY-exit closes (user-initiated closes only). Cancel-defaulted so a reflexive Enter/Escape dismisses safely. One generic dialog (not bespoke) so future yes/no prompts reuse it.
- **2026-06-30 (S31) — Re-ran CI on the flaky DMG failure rather than hardening the maker.** The `hdiutil detach … No such file or directory` is a known electron-forge/appdmg race; every prior release built the DMG fine, so it's a one-off, not a regression — a re-run (same commit, fresh runner) was the fastest path to ship and it cleared on attempt 2. Hardening `maker-dmg` with a retry is logged as an *optional* backlog item, not bundled into a feature release. (The release/tag steps are gated behind Build DMG, so this failure meant NO release published — unlike the post-release Homebrew-cask failure.)
- **2026-06-30 (S31) — Reinstalled the local app from the canonical DMG, not the hook build.** The post-commit hook already `electron-forge package`s + copies to `/Applications` on every commit, but that build self-reports 1.0.0. Installing the *released* DMG sets the correct version string + canonical signed bits. Used `ditto` over the running bundle (no force-quit — the session may be inside Patton; macOS keeps the running process's inodes alive, so replacing on disk is safe), then the user relaunches. **Caveat found post-hoc**: the post-commit hook re-`package`s + copies a 1.0.0 build to /Applications on the *next* commit (incl. this checkpoint), reverting the version string — so the "correct version string" goal is unachievable while the hook runs; the real fix is to stamp the version into `package.json`/the build, not to re-install the DMG. The install still validated the release bits + the no-force-quit `ditto` path.
- **2026-06-08 (S30) — Promoted DOM to the *default* renderer, not the opt-in it was in S29.** The S29 toggle's DOM mode held over real use (user confirmed the glyphs stopped), so the bet behind keeping WebGL default ("most fresh users won't hit the bug") no longer justified its asymmetric downside: an unlucky fresh user gets garbled text + a self-guided hunt for the fix + real uninstall risk, vs DOM's perf cost that's invisible for normal terminal work on a modern Mac. Flipped `DEFAULTS.RENDERER` to `'dom'`; existing users' saved settings still override, so only no-preference/fresh installs move. Considered keeping WebGL default + a one-time "seeing garbled text? switch" toast — rejected as a discoverability band-aid over just removing the failure mode by default. WebGL remains a one-click opt-in for its perf.
- **2026-06-08 (S30) — Fixed the Homebrew tap by hand rather than refreshing the token.** User declined the ~3-min `HOMEBREW_PAT` regeneration. A manual cask bump (version + verified sha256) pushed via the no-expiry gh OAuth token unsticks `brew` immediately with zero user action — the expired PAT only blocks the *CI* auto-update step, not a local push. Verified the checksum by streaming the published DMG through `shasum` (not trusting CI's table blindly) because a wrong cask hash silently breaks every `brew install`. Trade-off accepted: each future release re-needs this ~30s manual step until the token is refreshed; logged in Gotchas + Next Steps so it's not a surprise.

## Gotchas
- **Claude Code v2.1.x "fullscreen rendering" breaks selection AND can re-trigger glyph corruption** (S29, 2026-06-05). Opt-in research preview (alt-screen buffer + mouse capture; the "Jump to bottom" pill is the tell). Mouse capture sends drags to Claude Code not the terminal → "can't highlight text"; the alt-screen path also re-stresses xterm's WebGL atlas. Disable via `/tui default` (full revert) or `CLAUDE_CODE_DISABLE_MOUSE=1` (keep flicker-free). Patton's answer: the renderer toggle + `macOptionClickForcesSelection`. Docs: `code.claude.com/docs/en/fullscreen`.
- **On macOS, xterm v6 ignores Shift for selection during mouse mode** (S29). `shouldForceSelection` = `isMac ? altKey && macOptionClickForcesSelection : shiftKey`. So on Mac you MUST set `macOptionClickForcesSelection: true` (now set in `terminal-view.ts`) and hold **Option** to drag-select while an app (Claude Code fullscreen, vim, tmux, htop) holds the mouse. Without it there is no selection escape hatch at all.
- **DOM renderer is the structural fix for glyph corruption — and as of S30 it's the DEFAULT** (`DEFAULTS.RENDERER='dom'`). It never loads (or disposes) the WebglAddon → xterm falls back to DOM → no GPU glyph atlas → the whole corruption class is structurally impossible. Fresh installs land here; WebGL ("GPU — fast") is a one-click opt-in (palette → "Switch to GPU Renderer", or Settings → Text Renderer). Existing users' saved choice overrides the default. Confirm DOM is active by `[RENDER] *atlas flush` lines being ABSENT in `main.log` (flush paths no-op when `!webglAddon`). Cost: marginally heavier on huge output bursts.
- **`npm run package` can be blocked by a prod-dependency CVE, not a code error** (S29). The script is `npm audit --omit=dev --audit-level=high && electron-forge package` — one high-severity *production* advisory fails the gate before the build runs (S29: `fast-uri`). Diagnose with `npm audit --omit=dev --audit-level=high`; fix transitive vulns with a `package.json` `overrides` pin, not `audit fix --force`. Dev-only vulns don't count against this gate.
- **`backgroundThrottling: false` in `webPreferences` is load-bearing** for the WebGL atlas-corruption defence (S27, 2026-05-07). With Chromium's default (true), the renderer is suspended/throttled when Patton goes background → on resume the WebGL texture state is silently stale or corrupted → user sees garbled glyphs until window-resize forces a reflow. Removing this setting will reintroduce the bug. Side effects: visibilityState reports 'visible' even when occluded (any "is app in background?" check must use `document.hasFocus()` not `document.hidden`); minor extra background CPU. The visibility-flush handler in `terminal-view.ts` is the recovery fallback — both layers exist deliberately.
- **`document.hidden` is unreliable in Patton** (S27). Because `backgroundThrottling: false` pins the Page Visibility API to 'visible' even when occluded, `document.hidden` is approximately always false in production. Use `document.hasFocus()` for "is the user looking at Patton?" gating. Already replaced in `app.ts:33` for the notification path; if you find another `document.hidden` callsite, it likely needs the same fix.
- **Renderer `console.*` calls don't reach `main.log` unless they go through `rlog()`** (S27). `src/main/logger.ts` only tees the main-process console. Any new `[RENDER]` or other diagnostic line you want in the file log MUST use `rlog()` from `src/renderer/services/renderer-logger.ts` — `console.info` alone reaches DevTools only and is invisible to packaged-app launches. This is exactly the gap that made S25's "is the periodic timer firing?" question unanswerable for ~10 days. `rlog()` keeps the DevTools console output too, so it's a strict superset of `console.*` for diagnostic purposes.
- **`[RENDERER]` prefix in `main.log` distinguishes renderer-bridged lines from native main-process lines** (S27). Lines starting `[RENDERER]` came through the IPC bridge from a renderer; everything else is native main-process. Useful when grepping — e.g. `grep '\[RENDERER\] \[RENDER\] resume atlas flush' main.log` finds visibility-triggered flushes specifically, vs `grep '\[RENDER\] snapshot saved'` (no `[RENDERER]` prefix) which is the main-process snapshot writer.
- **xterm WebGL atlas eviction = the "garbled glyphs" root cause; two triggers, now sidestepped by DOM-default** (S25/S27). Saturation-driven (long sessions emit many glyph variants → fixed-size atlas LRU-evicts slots without repointing buffer cells → wrong chars in scrollback) AND focus/refocus-driven (Chromium suspends the renderer in background → GPU state silently corrupts). Identical symptom, different trigger. Only matters on WebGL now that S30 made DOM the default; a WebGL opt-in user who hits it can rely on the S25/S27 defences (periodic + visibility/focus `clearTextureAtlas()`, `backgroundThrottling:false`, ⌘⇧K reset) or just switch to DOM. Full saga + per-defence rationale in `docs/session-archive.md`.
- **`clearTextureAtlas()` is on Terminal, not WebglAddon** (xterm 6 typings — `node_modules/@xterm/xterm/typings/xterm.d.ts`). Public API; cheap; rebuilds atlas lazily on next render. **No addon disposal needed.** S24's `setCustomTheme()` path disposes+reloads the WebglAddon (more expensive, ~1 frame flicker) — keep that pattern only for when colors actually change. For periodic / heuristic flushes, plain `clearTextureAtlas()` is the right tool.
- **`app.getVersion()` in `main.log` returns `1.0.0` even after CI-versioned releases.** The release script tags git but doesn't bump `package.json` (per repo convention — git tags are source of truth). The `Patton main process started (vX.Y.Z, ...)` startup line is therefore meaningless for diagnosing "is the running build current?". Use the asar mtime instead: `ls -lt /Applications/Patton.app/Contents/Resources/app.asar` — that timestamp matches when `npm run package` last ran. The same `1.0.0` shows in `/Applications/Patton.app`'s `CFBundleShortVersionString`: even after installing the *released* DMG (which carries the real version), the **post-commit hook re-`package`s + copies a 1.0.0 build over it on the very next commit** — so a DMG install's correct version string never survives the next commit (S31). The durable fix is to stamp the version into `package.json`/the build.
- **Homebrew tap auto-updates via a write-scoped SSH deploy key** (S33, 2026-07-07 — replaced the expired `HOMEBREW_PAT`). `michaeljryoung/homebrew-patton` holds one cask, `Casks/patton.rb` (local clone `~/Projects/homebrew-patton`). `release.yml`'s `Update Homebrew cask` step clones/pushes it **over SSH** using the `HOMEBREW_DEPLOY_KEY` secret (private half of a read-write deploy key on the tap — least-privilege, no expiry). The old broad `HOMEBREW_PAT` expired 2026-03-09 and *failed* the step every release S28–S32 (each needed a manual bump); it's now unused and deletable. The guard now skips gracefully when the key is absent. **Manual fallback** if the step ever fails: edit `version` + `sha256` (the `url` auto-resolves from `version`), push via gh OAuth — VERIFY the sha first (`curl -sL <dmg-url> | shasum -a 256`; a wrong hash silently breaks every `brew install`; it's also in the release body's `### Checksums` table). To rotate the deploy key: `ssh-keygen` → `gh repo deploy-key add <pub> --repo michaeljryoung/homebrew-patton --allow-write` → `gh secret set HOMEBREW_DEPLOY_KEY --repo michaeljryoung/patton < <priv>`.
- **Drive the running dev app headlessly via the Node inspector to verify UI** (S33). `node -e 'process._debugProcess(<mainPID>)'` opens port 9229 on the Electron MAIN process; a CDP `Runtime.evaluate` there can `require('electron')` and `webContents.executeJavaScript(...)` into the renderer — so you can split/close panes, toggle UI, read DOM state, and `capturePage()` (offscreen) WITHOUT touching the user's screen (safe while they're on a call). Two gotchas: `Runtime.evaluate` needs `includeCommandLineAPI:true` or `require` is undefined; and a long-lived session accumulates stale async rejections that surface as spurious `require is not defined` — restart the app if evals wedge. This is how S33 diagnosed the pane-close bug + verified the notes panel without a visible window.
- **CI's "Build DMG" step can fail on a flaky `hdiutil detach` race — just re-run** (S31, 2026-06-30). electron-forge's `maker-dmg`/appdmg intermittently dies with `hdiutil detach /Volumes/Patton … No such file or directory` (the volume auto-ejected before appdmg unmounted it). `package` + `zip` succeed; only the DMG maker races. Transient → `gh run rerun <id> --failed` (fresh runner) clears it (S31: green on attempt 2). Not a code bug — every prior release built fine. **The tag + GitHub-release steps are gated behind Build DMG**, so a failure here means NO release published — unlike the post-release Homebrew-cask failure, which leaves the release intact.
- **`setCustomTheme()` is called BEFORE `mount()` on new tabs that inherit the current theme** (`tab-manager.ts:153-155`). Any WebGL-aware code in setCustomTheme must guard `if (this.webglAddon)` — otherwise it'll try to dispose/reload an addon that doesn't exist yet. The guard is in place; don't remove it when refactoring. Post-mount theme changes hit the real flush path; pre-mount just sets the theme option for the upcoming `loadWebgl()` call.
- _Gotcha "garbled-glyph symptom is not always a Patton bug — reproduces in iTerm2; discriminate via Apple Terminal.app; `atsutil databases -remove` resets CoreText cache" (S27) archived 2026-07-07 S33 trim → `docs/session-archive.md` (render saga closed, DOM is default)._
- **Committing used to kill a running Patton — the post-commit rebuild replaced `/Applications/Patton.app` under it** (S36, 2026-08-01). `forge.config.ts`'s `postPackage` install step ran `rm -rf /Applications/Patton.app && cp -R …`, and `.git/hooks/post-commit` runs `electron-forge package` on **every** commit. Deleting the bundle out from under a live process kills it the next time it lazily loads from that bundle — it dies quietly, with no crash dump (looks like a clean exit, which is why it's easy to misattribute). This corrects the S34 session-log claim that the hook is "safe during live app use" because it has no `pkill`: the absence of a `pkill` was never the whole story. **Fixed in S36** — the step now uses `ditto "$appPath" "$dest"`, which overwrites in place and leaves the running process's open inodes alive (the same no-force-quit path S31 validated for DMG installs). Trade-off: files deleted in a newer build linger, so `rm -rf /Applications/Patton.app` by hand for a truly clean install. If a running Patton ever dies for no clear reason right after a commit, check this step first.
- **macOS does NOT hot-swap a replaced `.app` bundle.** After `npm run package` reinstalls to `/Applications/Patton.app`, the running Patton process is still the OLD binary. ⌘Q + relaunch required to pick up new code. Detection recipe: `ls -lt /Applications/Patton.app/Contents/Resources/app.asar` (asar mtime) vs `ps -o lstart= -p $(pgrep -f Patton.app | head -1)` (process start). If process start < asar mtime, the running build is stale. S26 (2026-04-27 evening) hit this exactly. Second confirmation channel: grep `main.log` for the post-fix log signature.
- **Packaged asar minifies identifier names but preserves literal values.** Verifying a shipped change: don't grep for original variable names (`event.detail !== 2` minifies to `a.detail!==2`). Grep for literal string constants (`'Reset Renderer'`, regex source strings) — those survive minification.
- **Packaged Electron apps launched from Dock/Finder route main-process stderr to `/dev/null`.** Without a file logger, every main-process signal is invisible. See `src/main/logger.ts`. Renderer console doesn't even reach that — see the rlog gotcha above.
- **WebGL glyph atlas is keyed by color and can go stale on theme swap.** xterm's WebGL renderer caches glyphs keyed by `(char, bold, italic, fg_color, bg_color, ...)`. `terminal.options.theme = newTheme` mutates resolution but does NOT invalidate the cache — fix is dispose+reload the WebglAddon on every theme change. Same shape as the `minimumContrastRatio` / `onContextLoss` story.
- **xterm.js v6 registers no kitty/CSI-u handler by default.** Apps sending `\x1b[>1u` (push progressive-enhancement flags) get silently ignored — terminal keeps sending `\r` for Enter, not `\x1b[13u`. Patton's current consumers (Claude Code, fish, neovim) work fine without it.
- **OSC 133 `'prompt'` is not "awaiting input".** Fires on every prompt redraw — shell startup, session restore, SIGWINCH, `clear`, async-prompt refreshes (Starship, Powerlevel10k). Use `pane.ts fireCommandDone()` for the meaningful-transition signal.
- **Layering multiple `window.on('close')` handlers doesn't work for guards.** Electron runs every registered 'close' handler even if one calls `e.preventDefault()`. The guard must live INSIDE the destructive handler so teardown only runs when the guard passes.
- **xterm.js `attachCustomKeyEventHandler` fires for BOTH `keydown` AND `keypress`.** Returning `false` only on `keydown` still lets `keypress` through, causing xterm to send `\r`. Must return `false` for both event types.
