# Patton

Always-passthrough terminal with a floating compose panel for drafting multi-line input.

## Tech Stack
- **Electron** (v44) with Vite 8 + TypeScript via Electron Forge (v8; needs Node 22.13+)
- **xterm.js** v6 (`@xterm/xterm`) — terminal rendering (WebGL addon)
- **node-pty** — PTY spawning in main process
- **electron-store** — persistent settings + history

## Architecture

```
src/
├── main/           # Electron main process (PTY, IPC, menus, settings store, bookmarks,
│                   #   project board, link-open policy, Claude Code hook installer, logger)
├── preload/        # contextBridge API (type-safe IPC bridge)
├── renderer/       # UI components, services, styles
│   ├── components/ # Tab, pane, terminal view, editor input, settings, command palette,
│   │               #   bookmarks panel, project board, tab hover card, etc.
│   ├── services/   # Tab manager, history, keybindings, program status (OSC 7501),
│   │               #   file/OSC 8 links, sessions, project boards, renderer logger
│   └── styles/     # CSS with design tokens + auto dark/light mode
└── shared/         # IPC channel constants, shared TypeScript types, shortcuts
resources/          # Shell integration scripts (zsh, bash) and the Claude Code Stop hook
scripts/            # forge-package.sh, release, health, check-*.mjs suites
```

## Commands
- `npm start` — dev mode with hot reload
- `npm run package` — prod-dependency audit, then build through `scripts/forge-package.sh`, which installs over `/Applications/Patton.app` (`PATTON_NO_INSTALL=1` builds without installing)
- `npm run install-app` — the same build and install, without the audit
- `npm run make` — create DMG installer
- `npm run lint` — ESLint; `npx tsc --noEmit` — type check
- `npm run audit` — the prod-dependency CVE gate on its own
- `npm run health` — `scripts/patton-health.sh` diagnostics
- `npm run release [-- patch|minor|major]` — manual release (CI handles this automatically)

## Verifiers

```bash
npm run lint && npx tsc --noEmit && PATTON_NO_INSTALL=1 npm run package
```
A build is proven by the asar's mtime, not the exit code (Gotchas: Forge exit codes).

## Key Conventions
- All colors use CSS variables (`:root` + `@media prefers-color-scheme`)
- All interactive elements have ARIA attributes
- Resize observers are debounced (100ms)
- PTY data is write-coalesced (4ms buffer)
- electron-store needs CJS/ESM interop: `(mod.default || mod)`
- Entry files must match package.json `main` field naming: Forge 8's Vite plugin emits `.vite/build/main.cjs` and `preload.cjs`, so `main` is `.vite/build/main.cjs` and `window-manager.ts` loads `preload.cjs`

## Mission Synthesis
Patton is a macOS Electron terminal (xterm.js, node-pty) built to close the gaps Claude Code exposes in stock terminals: colour queries, contrast, attention signals, and finding your way across many parallel sessions. It ships as a DMG plus a Homebrew cask, CI-versioned on push to main (patch ≤500 lines, else minor; a head commit carrying `[no-release]` skips the whole push), now at **v1.15.2** on Electron 44. The attention model moved from Claude's title glyphs (S37) to a Stop hook whose OSC 777 verdict parks a tab with a hollow ring while Claude waits on its own background work (S40–S42), and from v1.14 to Claude Code's own OSC 7501 status reports, with the older path kept behind a Settings switch. v1.14 added the checkpoint clock (context used since the last `/checkpoint`), worktree-aware names, session-aware bookmarks and palette, a tab hover card and OSC 8 links behind a policy that never launches a program. S44 turned finding a project into a place rather than a list: every new tab opens on a tile board of Michael's project list (the markdown table his `cc` launcher reads, which now has two readers), grouped into tinted themes he arranges, with + Project writing back only into that table's Project/Path rows and a Wake button that starts his keep-awake command in a background tab. v1.15's board has now run live at launch, on ⌘T and through a drag; little of v1.14 has, so the next arc is the remaining live checks (a tile click, then v1.14's), then Forge 8. Builds stay out of /Applications while Michael works in Patton (worktrees, `PATTON_NO_INSTALL=1`, `git merge --ff-only`), but once he says to update the local app, every verified release that session installs from its tag; a Forge exit code is no proof of a build (Forge 7 exited 0 without packaging on Node 26), so proof is the asar's mtime. ## Gotchas
- **`'SF Mono'` in a CSS font stack never draws in Chromium on macOS** (S45). macOS doesn't expose SF Mono to apps by family name (it ships inside Terminal.app and as a hidden system font), so until v1.16 Patton's default, its "SF Mono" option and "Fira Code" (not installed) all drew Menlo, and Settings → Font Family looked dead. `src/main/system-fonts.ts` now reads the Mac's own Terminal.app faces (never bundled: Apple's licence) and the renderer registers them as a FontFace before any terminal opens; `node scripts/check-fonts.cjs` proves it in a hidden Electron window. Never assume a font in a stack draws: measure it.
- **One builder agent can't hold a ~5,000-line feature** (S44). The first board builder stopped at its context limit after the main module. What worked: split by file ownership, write the shared interface and who owns which files into both briefs, use parallel worktrees, then merge. The two halves met without a fix.
- **Every commit on main reinstalls /Applications/Patton.app, and Michael works inside it** (S41). The post-commit hook runs `scripts/forge-package.sh`, whose postPackage `ditto`s over the running app (survivable, but not wanted mid-session). Do code in a `.worktrees/` worktree (the hook exits there), verify with `PATTON_NO_INSTALL=1 npm run package`, move main with `git merge --ff-only` (no post-commit), and commit on main itself only with `PATTON_NO_INSTALL=1` in the environment (the hook inherits it). That includes `/checkpoint`: run `checkpoint-commit.py` with `PATTON_NO_INSTALL=1` (S44: without it, the checkpoint commit reinstalled the app from main, which reported "1.15.1+1" until the tag was reinstalled).
- **Renderer components can be checked headlessly in jsdom** (S41). Bundle the component with `node_modules/.bin/esbuild <entry> --bundle --format=cjs --platform=browser --loader:.css=empty`, set jsdom's window and document as globals with a stub `window.patton`, and dispatch events (drag events: a plain `Event` with `dataTransfer` and `clientY` defined on it). Install jsdom in the scratchpad, not the project. jsdom does no layout, so rect-based logic is only half-tested.
- **`backgroundThrottling: false` is load-bearing, and it makes `document.hidden` useless** (S27; two entries merged S41, originals in the archive). With Chromium's default throttling a backgrounded window's WebGL glyph atlas came back stale (garbled until a resize), so removing the setting brings that back for WebGL users. Side effect: the Page Visibility API always reports visible, so gate "is the user looking?" on `document.hasFocus()`, never `document.hidden` (already so in `app.ts:33`).
- **Main's IPC rate limiters refuse silently, so a burst caller loses data** (S43). `pty:get-cwd` (10/s) answered `''` past the limit and autosave saved it, so panes past the tenth reopened in `~` (v1.13.2); `settings:set` (10/s) dropped the last step of a slider drag or a held arrow (v1.14). Space burst calls (autosave refreshes cwds 120 ms apart), debounce rapid saves, and never persist a refused answer over a known value.
- **Answering Claude Code's `OSC 7501;?` probe makes Claude drop its ◐/✳ title glyph** (S43). From v1.14 Patton answers it (setting `programStatus`, default on), so a pane's Claude state comes from 7501 reports (`services/program-status.ts`, `Pane.claudeState`) and the title glyph + Stop-hook verdict are only the fallback for panes that never report. If dots misbehave, Settings → "Use Claude Code's own status reports" off restores the v1.13 path for Claude sessions started after the change; `grep '\[7501\]' main.log` shows probe answers and states. Only reports with `app=claude-code` count as Claude.
- **A file link may only open what can't run** (S43). `src/main/link-open-policy.ts` decides open / editor / reveal for every file link (bare text, markdown, OSC 8): realpath first, then only regular, non-executable view types open in their default app (HTML/SVG/PDF go to Chrome/Acrobat here, where page script can run); code goes to the editor; apps, scripts, installers, `.webloc` and unknown types are revealed in Finder. `scripts/check-link-open-policy.mjs` drives the real handler with recorders; never test by opening fixtures.
- **Michael's startup command is `cc`, a project picker, not `claude`** (S42). It always asks which project, so a bookmark tab that just typed it landed in the picker. A tab opened from a project bookmark now gets `PATTON_PROJECT_DIR` (first pane only; main exports the validated cwd, the renderer sends only `projectDir: true`), and `cc` in `~/Projects/claude-launcher/launcher.sh` uses it once to launch that project directly. Never assume what the startup command does.
- **electron-store fills `defaults` only at the top level** (S42). Patton's settings are one nested object, so a field added later is absent from every saved file: read it as `=== true` (off by default) or `!== false` (on by default), never bare.
- **A new per-pane setting must be applied in `Tab.createPaneInstance`, not only to existing panes** (S40). Until `8af2355`, `Tab.setFont/Scrollback/Theme/Renderer/CopyOnSelect` looped over `_panes`, so a split pane got none of them — on the default DOM renderer a split silently ran WebGL. The review of compose-first found it; keep the values on `Tab` and apply them at pane creation.
- **Forge exit codes are not proof of a build** (S40; Forge 8 in S45). Under Forge 7 on Node 26, `extract-zip` 2.0.1 drained the event loop: Forge exited 0, `out/` stayed empty and the postPackage hook never ran. Forge 8 (@electron/packager 20.3, no extract-zip) packages on Node 26, but the habit stays: build through `scripts/forge-package.sh` and prove it by `ls -l` of the asar (`out/…` for a no-install build, `/Applications/Patton.app/Contents/Resources/app.asar` for an install) being newer than the commit. The post-commit hook writes its output to `.git/post-commit-build.log`. Local `npm run make` needs Node 22–24: the DMG maker's `macos-alias` (nan 2.30) does not compile on Node 26, so install and make with `PATH=/usr/local/bin:$PATH` (Node 24) or CI's Node 22.
- **A Stop-hook verdict can land while the title still shows ◐** (S40). Claude Code emits each hook's `terminalSequence` as that hook finishes, and Michael's `closing-block-gate.py` can `block` the stop so the turn continues. `pane.ts` therefore stores the verdict and applies it only after ✳ has held 1.5 s; a verdict expires after 40 s (S42: ✳ appears only after every Stop hook ends, and `source-critic.py` makes that 4.5–31 s, so the original 10 s let stops fall through to the title path and go green while background work ran; longer would widen the window where a blocked stop's stale verdict parks a pane that then stops at a question or dialog); a parked pane never fires from the title path. `grep '\[DOT\]' main.log` shows stored/applied (with `afterMs`)/expired.
- **Claude Code's `terminalSequence` allowlist is OSC 0/1/2/9/99/777 + BEL** (S40). Anything else makes the field silently ignored. Patton's channel is `OSC 777;patton;…`; `OSC 777;notify;title;body` counts as attention like OSC 9.
- **Never tear a tab down before `window.close()`** (S37). The main close guard asks only while the window's PTYs are alive; disposing the last tab first made the prompt depend on an IPC race (Electron 44 lost it, so ⌘W quit silently). Any close path that should confirm must reach the guard with its shells still running.
- **The release workflow reads only the head commit's whole message for the no-release marker** (S37). A trailing docs commit carrying it, or a commit body that merely quotes it, skips the release for the entire push. Keep a code commit on top, or end with a marker-free `release:` commit. Builder agents add the marker to their own code commits unprompted (S45: both close-dialog commits carried it), so check `git log --format=%B origin/main..` for it before every push.
- **`npm run package` can be blocked by a prod-dependency CVE, not a code error** (S29). The script is `npm audit --omit=dev --audit-level=high && electron-forge package` — one high-severity *production* advisory fails the gate before the build runs (S29: `fast-uri`). Diagnose with `npm audit --omit=dev --audit-level=high`; fix transitive vulns with a `package.json` `overrides` pin, not `audit fix --force`. Dev-only vulns don't count against this gate.
- **Renderer `console.*` calls don't reach `main.log` unless they go through `rlog()`** (S27). `src/main/logger.ts` only tees the main-process console. Any new `[RENDER]` or other diagnostic line you want in the file log MUST use `rlog()` from `src/renderer/services/renderer-logger.ts` — `console.info` alone reaches DevTools only and is invisible to packaged-app launches. This is exactly the gap that made S25's "is the periodic timer firing?" question unanswerable for ~10 days. `rlog()` keeps the DevTools console output too, so it's a strict superset of `console.*` for diagnostic purposes.

- **Homebrew tap or cask trouble** (the release's `Update Homebrew cask` step fails, `Permission denied (publickey)`, a cask to fix by hand, a key to rotate) → read `docs/reference/homebrew-tap.md` first. Never re-run a failed release to fix the cask: it cuts a duplicate release.
- **macOS does NOT hot-swap a replaced `.app` bundle.** After `npm run package` reinstalls to `/Applications/Patton.app`, the running Patton process is still the OLD binary. ⌘Q + relaunch required to pick up new code. Detection recipe: `ls -lt /Applications/Patton.app/Contents/Resources/app.asar` (asar mtime) vs `ps -o lstart= -p $(pgrep -f Patton.app | head -1)` (process start). If process start < asar mtime, the running build is stale. S26 (2026-04-27 evening) hit this exactly. Second confirmation channel: grep `main.log` for the post-fix log signature.
- **Packaged asar minifies identifier names but preserves literal values.** Verifying a shipped change: don't grep for original variable names (`event.detail !== 2` minifies to `a.detail!==2`). Grep for literal string constants (`'Reset Renderer'`, regex source strings) — those survive minification. To read one file out of the asar, run `npx asar extract-file` from a scratch folder: it writes the file's basename into the current directory, so run from the repo root, extracting `node_modules/<pkg>/package.json` overwrites Patton's own `package.json` (S43: it did, and the post-commit build that was reading it failed).
- **OSC 133 `'prompt'` is not "awaiting input".** Fires on every prompt redraw — shell startup, session restore, SIGWINCH, `clear`, async-prompt refreshes (Starship, Powerlevel10k). Use `pane.ts fireCommandDone()` for the meaningful-transition signal.
